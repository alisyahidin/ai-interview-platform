# Dev environment: mise for language runtimes, Docker Compose for stateful infra

We need a reproducible clean-machine setup (F29: no macOS or Docker path, environment setup fails on a clean Mac). We split the toolchain in two: `mise.toml` pins Ruby and Node (language runtimes), while `docker-compose.yml` runs Postgres and Redis (stateful infra). We considered a single `mise.toml` covering everything, and a fully Dockerized dev environment (including the app processes). We rejected mise-for-everything because Postgres/Redis would need mise's less-common plugin backends and lose the disposable-container reset a dev database usually wants. We rejected full Docker because it adds volume-mount/live-reload overhead for no benefit within this deadline. The API's existing `Dockerfile` remains production/deploy-oriented only; it is not part of the dev bootstrap.
